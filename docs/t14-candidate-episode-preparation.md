# T14 candidate episode preparation

The repository retains the former 12-scene package in Git history and now contains a
deterministic, project-original replacement development package of 96 SVG repair episodes at
`benchmark/fixtures/repair/candidate/manifest.json`. The replacement crosses 24 visibly
distinct scene groups with four defect episodes per group. Whole scene groups are assigned by
a predeclared rule to 72 proposed-development and 24 proposed-held-out episodes (18/6 groups).

Under D042, the steward approved this redesigned, still-unfrozen 96-episode candidate together
with a separate 40-case non-normative diagnostic suite at
`benchmark/fixtures/repair/diagnostic/manifest.json`. The generated manifests are preparation
evidence, not approval of their bytes, aliases, allocation, or freeze.

This is candidate intake material only. The current or redesigned split is not frozen or normative, no agent output
is a human rating, and the package does not establish calibrated thresholds, E3 evidence,
independent validation, score compatibility, release readiness, or publication authority.

## Reproduction and validation

```bash
python scripts/build_t14_candidate_episodes.py --check
python scripts/validate_t14_candidate_episodes.py
python scripts/build_t14_diagnostic_episodes.py --check
python scripts/validate_t14_diagnostic_episodes.py
python scripts/validate_t14_prospective_statistics.py
```

The builder checks deterministic source bytes without repeating the validator's raster work.
The validator independently checks project-root confinement, symlinks, source commitments,
repository-native SVG safety inspection, canonical 512-pixel opaque-white render hashes,
operation-aware before/after predicates, preservation annotations, visible edits, group
isolation, and the proposed 72/24 balance.

The package deliberately records its 24 dependence clusters and shared repaired references.
Any later uncertainty analysis must use the scene group as the resampling unit. Candidate file
names, declared roles, defect identifiers, and requirements expose source labels and must not
be passed directly to a human-rating interface. A separate alias-only blinded manifest may be
created only after a fresh benchmark-steward freeze decision.

Three exact-commit advisory reviews are retained under `benchmark/evidence/advisory/t14/`.
They accept the package as local candidate preparation while recommending revisions before
any normative freeze. The later validator hardening in `de9a13d` addresses the
target-specific move concern without altering candidate assets: displaced rear wheels must
be vertically realigned, and repaired foot endpoints must move closer to an unchanged pedal.
The redesign addresses the prior recommendations with geometry-derived scene signatures,
family-specific moderate/severe parameters, and separately governed under-repair, over-edit,
introduced-defect, boundary, and invalid cases. It remains fixture evidence until advisory
re-review and a later exact-hash steward freeze decision.

The legacy manifest and its commitments remain available through Git history as prior
development evidence; regenerated bytes are schema version 2 and are not treated as the same
candidate. Diagnostics use distinct identifiers and `normative_eligible: false`. After a fresh
three-role panel review, agents may prepare an exact-hash freeze packet; only a later recorded
steward decision may freeze it.
